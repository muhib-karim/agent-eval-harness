The bug was in `find_last`. `_right` returns the insertion point just *after* the last element equal to `target`, so the last match is at `index - 1`. The old code checked `items[index]`, which is the element after the run (or out of range), so it returned -1.

While fixing it I also made each public function call `len()` only once, as the constraint requires. `find_first` and `count_range` previously called it twice. The helpers now take the length as a parameter. Public behaviour is unchanged.

```python
"""Binary-search helpers over an ascending list."""


def _left(items, target, n):
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if items[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo


def _right(items, target, n):
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if items[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo


def find_first(items, target):
    """Index of the first element equal to target, or -1."""
    n = len(items)
    index = _left(items, target, n)
    if index < n and items[index] == target:
        return index
    return -1


def find_last(items, target):
    """Index of the last element equal to target, or -1."""
    n = len(items)
    index = _right(items, target, n) - 1
    if index >= 0 and items[index] == target:
        return index
    return -1


def count_range(items, low, high):
    """Number of elements x with low <= x <= high."""
    if low > high:
        return 0
    n = len(items)
    return _right(items, high, n) - _left(items, low, n)
```
