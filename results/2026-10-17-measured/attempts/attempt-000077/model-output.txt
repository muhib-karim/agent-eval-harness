def merge_intervals(intervals):
    """
    Merge overlapping and touching closed intervals.
    
    Args:
        intervals: An iterable of pairs (start, end) representing closed intervals.
    
    Returns:
        A sorted list of disjoint tuples (start, end).
    
    Raises:
        ValueError: If a pair has wrong length, non-integer endpoints, or start > end.
    """
    validated = []
    if intervals is None:
        return []
    
    for pair in intervals:
        # Check if it's a pair (has length 2)
        try:
            if isinstance(pair, (str, bytes)):
                raise ValueError("Invalid interval: string is not a valid interval pair")
            length = len(pair)
        except TypeError:
            raise ValueError("Invalid interval: endpoints must be a pair")
        
        if length != 2:
            raise ValueError(f"Invalid interval: expected 2 elements, got {length}")
        
        # Convert to list access to handle any sequence/I iterable
        items = list(pair)
        start, end = items[0], items[1]
        
        # Validate endpoints are integers (not bool)
        for val in (start, end):
            if isinstance(val, bool) or not isinstance(val, int):
                raise ValueError(f"Invalid endpoint: {val!r} is not an integer")
        
        # Validate start <= end
        if start > end:
            raise ValueError(f"Invalid interval: start {start} > end {end}")
        
        validated.append((start, end))
    
    if not validated:
        return []
    
    # Sort by start, then end
    validated.sort(key=lambda x: (x[0], x[1]))
    
    # Merge intervals
    merged = [validated[0]]
    for start, end in validated[1:]:
        last_start, last_end = merged[-1]
        # Merge if overlapping or touching (start <= last_end + 1 covers touching)
        if start <= last_end:
            # Extend the current interval
            if end > last_end:
                merged[-1] = (last_start, end)
        else:
            merged.append((start, end))
    
    return merged

Wait, let me reconsider the "touching" part. The task says "merging overlap and touching endpoints." In mathematical terms, closed intervals [a, b] and [c, d] are touching if b+1 == c (adjacent integers) or if they share an endpoint. But "touching endpoints" typically means they share an endpoint: b == c. Let me re-read: "merging overlap and touching endpoints."

Two closed intervals overlap if they share at least one point: [1,3] and [2,4] overlap at 2,3. They touch if they share just an endpoint: [1,3] and [3,5] touch at 3. So merging overlap and touching means merge when start <= last_end (since start == last_end means they touch). Adjacent like [1,2] and [3,4] do NOT touch in the interval sense (2 != 3). 

Actually, "touching endpoints" - if interval A ends at 3 and interval B starts at 3, their endpoints touch. That's start <= last_end. My original condition `start <= last_end` is correct for this interpretation.

But some might interpret "touching" as consecutive integers (e.g., [1,2] and [3,4]). However, "touching endpoints" literally means the endpoints touch, i.e., share the same value. So `start <= last_end` is correct.
